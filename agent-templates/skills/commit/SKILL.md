# 提交改动

## 步骤

1. **先看清现场**（三条并行跑，别串行）：
   - `git status` —— 有哪些改动、哪些是新文件。
   - `git diff`（未暂存）与 `git diff --staged`（已暂存）。
   - `git log -n 5 --oneline` —— **照这个仓库已有的提交风格写**，不要自创格式。
2. **判断该不该分多次提交**：改动里混着互不相关的几件事（例如一个 bug 修复 + 一次重构 + 一批格式化）时，**先问用户**要不要拆；用户没要求就按一件事一次性提交，别自作主张拆。
3. **暂存**：**按文件名逐个 `git add`**，不要用 `git add -A` / `git add .` —— 那会把凭据、构建产物、大二进制一起带进去。
4. **写提交信息**：说清**为什么**这么改，而不是复述 diff 里就能看到的「改了什么」。一到两句，聚焦动机。
5. **提交**，然后 `git status` 确认结果。

## 绝对不能提交

`.env` 及任何含凭据的文件、私钥、`node_modules`、构建产物、大于几 MB 的二进制。
**发现暂存区里有这类文件就停下来告诉用户**，不要「顺手删掉」也不要提交（删除是用户的决定）。

## 边界

- **不 `git push`**，除非用户明确要求；也**不** `--force`。
- **不 `git commit --amend`** 一条已经推上去的提交，除非用户明确要求。
- **不更新 git config**。
- 提交信息**不写** emoji、不贴「由 AI 生成」这类签名（除非用户要求）。
