# Lunac 技能目录（skills）

把你自己的技能放进这个目录，agent 启动时会扫描它，并且**只把「名称 + 描述」列进系统提示词**（渐进披露）；模型判断需要时才调用 `Skill` 工具取回正文 —— 所以技能再多也不会把上下文撑爆。

## 目录结构

```
skills\
  <技能名>\
    SKILL.md          ← 必须叫这个名字，否则整个目录会被跳过
    ...               ← 该技能自带的脚本 / 参考资料，正文里用相对路径引用
```

## 自带的脚本 / 参考资料

技能目录里**除 `SKILL.md` 之外的文件**会被自动登记：模型调用这个技能时，会在返回里收到一份文件清单（形如 `scripts/run.py`、`assets/tpl.md`），抬头写明「相对于 `<技能目录>`」—— 它就能用 `Read` / `Glob` 自己去取，正文里直接写「用 `scripts/run.py` 处理」即可，**不用**写绝对路径。

登记规则（保守，宁少勿滥）：

- 递归到**第 3 层**为止（`scripts/run.py` 是 2 层，`a/b/c.txt` 是 3 层，再深不列）；
- 最多列 **40 个**文件，超了会如实写一行「还有没列出的」；
- 跳过隐藏项（`.` 开头，含 `.git` / `.DS_Store`）与 `node_modules` / `target`；
- **不跟随符号链接**（既不递归进去也不列出）—— 这样「报出来的路径一定在这个技能目录内」。
- 这份清单**不进系统提示词**（它有变就会让端点侧的前缀缓存整段作废），只在调用技能时按需附上。

> 想让脚本能被直接执行：正文里写清调用方式（例：`python scripts/run.py <file>`）。执行命令仍走 `Bash` / `PowerShell`，照常弹审批卡。

## SKILL.md 格式

```markdown
---
name: my-skill
description: 一句话说明这个技能做什么、什么时候该用它（≤ 250 字符）
---

正文（Markdown）。写清楚步骤、约束和示例。

可以用 `$ARGUMENTS` 占位符：用户调用技能时传的参数会替换到这里。
```

## 两种执行模式

默认（上面这种）是 **inline**：模型调 `Skill` 之后拿到**正文**，然后在**当前对话**里自己照着做。

再加一个 `context: fork` 就变成 **fork** 模式：`Skill` 会**派生一个子代理**去执行这个技能，主对话只收它做完之后的报告。适合「步骤多、中间要读一堆文件」的技能 —— 中间过程不进主对话，省上下文。代价是：这类技能**会弹审批卡**（派子代理出去干活要先确认）、**计划模式下不可用**、且**不能并行**。

```markdown
---
name: my-forked-skill
description: 一句话说明这个技能做什么（≤ 250 字符）
context: fork
allowed-tools: Read, Glob, Grep      # 逗号分隔；不写 = 子代理的全部工具
---

正文写清楚「做完什么、交付什么」。子代理看不到你当前的对话，
所以缺什么信息要写在这儿，或者从 `$ARGUMENTS` 传进去。
```

`allowed-tools` 只能从子代理本来就有的内置工具里挑（`Read` / `Write` / `Edit` / `Bash` / `PowerShell` / `Glob` / `Grep` / `WebSearch` / `WebFetch` / `AskUserQuestion` / `TodoWrite` / `Skill`）；写了但一个都对不上就是**一件也不给**。系统提示词里这类技能会带 `[subagent]` 标记。

## 生效方式

- 在 Lunac 设置 ·「技能扩展」面板里增删改 → 面板会自动重启 agent，立即生效。
- 直接改这个目录的文件 → 需要重启 Lunac（或切换一次思考开关）让 agent 重新扫描。
- 技能清单**按目录名排序**后拼进提示词（顺序抖动会整段作废端点侧的前缀缓存）。

## 关于本目录里的示例

`_example\SKILL.md.example` 是一份可以直接照抄的模板。它**故意不叫 `SKILL.md`**，所以不会被加载、也不会出现在模型看到的清单里 —— 想启用就把它改名成 `SKILL.md`。
