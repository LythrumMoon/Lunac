# 系统化调试

**铁律：没有复现就没有修复。** 在能稳定重现问题之前，任何改动都是猜。

## Phase 1 — 复现与证据

1. **拿到失败的确切形态**：完整报错文本、退出码、触发步骤、稳定还是偶发。
2. **自己跑一遍**，别只看调用方的描述。跑不起来就先解决「跑不起来」。
3. **缩小范围**：二分（注释掉一半 / 换更小的输入 / 换一条路径）。写下每次实验的结果 —— 排除掉的假设和证实的假设一样重要。
4. **红了就停**：这一步没做完（或做不了）就**不要**进入 Phase 2，改成如实回报「没能复现，需要 X」。

## Phase 2 — 提假设

- 一次只留**一个**当前假设，写成一句可证伪的话（「因为 A，所以 B」）。
- 优先怀疑**最近改过的那一处**（diff / 新加的依赖 / 新改的配置），而不是「一直好好的那部分」。
- 常见真凶排序：数据形状与预期不符 → 时序 / 并发 → 资源与生命周期 → 环境差异 → 真的逻辑写错。

## Phase 3 — 最小验证

- 设计一个**能证伪**该假设的最小实验：加一行日志 / 打印入参 / 写一个只跑那条路径的小用例。
- 实验要能区分「假设成立」和「假设不成立」—— 两种结果都要有对应的现象。
- 结果与假设不符 ⇒ **回到 Phase 2 换假设**，不要在同一假设上反复加码。

## Phase 4 — 修复与回归

1. 改在**根因**上，不在症状上（吞异常、加重试、放宽断言都是在把问题往后推）。
2. 修复必须**带一条能钉住它的测试或可重复步骤**；「我手动试过了」不算。
3. 回头确认 Phase 1 的复现路径现在真的不失败了，并检查有没有被这次改动波及的相邻功能。

## 红旗（出现就停手回到 Phase 1）

- 开始「先改改看行不行」。
- 连续两次修复都没解决，但你在改同一个地方。
- 说不清现在这个假设为什么可能成立。
- 打算用「加个 try/catch」「加重试」「先跳过这个用例」收场。

## 回报格式

```
现象：<可复现的失败形态>
根因：<file:line + 一句话>
证据：<哪次实验证实了它>
修法：<改了什么 + 钉住它的验证>
未覆盖：<这次没查的相邻面 / 仍不确定的点>
```
